ЛАБИ 1–10 — ЩО ЗАПУСКАТИ ПО ПОРЯДКУ
====================================

Позначки на початку блоку кажуть, ДЕ набирати команди:
  [МАК]        — Terminal на Маці
  [VM]         — віртуалка; на Маці: multipass shell linux-lab   (запрошення ubuntu@linux-lab)
  [КОНТЕЙНЕР]  — з VM: lxc exec ubuntu-node -- bash             (запрошення root@ubuntu-node, вихід: exit)

Друге/третє вікно: на Маці новий таб Terminal (Cmd+T) → multipass shell linux-lab.
Звіти редагуєш у VM: nano <файл>  (зберегти Ctrl+O Enter, вийти Ctrl+X).
⟦…⟧ у звітах — місця для значень з твоєї машини; команда, звідки взяти, — всередині дужок.

  cd ~/labs/lab-03/assets
  python3 worker.py
     → Ctrl+Z, потім:  jobs -l ;  bg %1 ;  fg %1 ;  Ctrl+C ;  echo $?      (буде 130)
  python3 worker.py > /dev/null & echo $! > worker.pid
  ps -o pid,ppid,stat,tty,cmd -p "$(cat worker.pid)"
  pgrep -af "python3 worker.py"
  kill -SIGSTOP "$(cat worker.pid)" ; ps -o pid,stat -p "$(cat worker.pid)"   (буде T)

  mkdir -p logs

  python3 worker.py >> logs/worker.log 2>> logs/worker-error.log & echo $! > worker.pid

Далі завдання 4 з методички (у тому ж файлі):
  4.1 видалити Environment=ROBOT_ENV=lab → daemon-reload → restart → status (код 2, exit-code)
  4.2 повернути Restart=on-failure і RestartSec=2 → daemon-reload → restart
      → через ~30 с: systemctl --user show robot -p NRestarts
  4.3 повернути Environment=ROBOT_ENV=lab → daemon-reload → systemctl --user reset-failed robot → restart
  4.4 systemctl --user show robot -p MainPID ; kill -SIGKILL <PID> ; через 3 с status і MainPID знову
  4.5 systemctl --user stop robot → status (не перезапустилась) → systemctl --user start robot
